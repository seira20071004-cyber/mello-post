# mellō — AI Instagram投稿スタジオ

Next.js App Router / React / TypeScript / Tailwind CSSで実装した、テーマ → 構成・文章 → AIイラスト → 編集 → 独立PNG・ZIP保存のWebアプリです。

**OpenAIへの実際のサーバーAPI処理を実装しています。固定の操作サンプルは、明示的に選ぶ場合だけ使用し、API失敗時にサンプルへすり替えません。**

## 投稿モードと文字の配置

新規投稿では「短い物語」を初期選択します。モードは文章生成前に選択してください。

| モード | 文章と構成 | 背景 |
| --- | --- | --- |
| 短い物語 | 表紙の短いフック → 日常の場面・会話 → 気づきと余韻。中面の見出し、強調帯、予告帯なし。本文20〜55文字を目安、上限80文字 | 場面ごとに生成。共通の人物・服装・画風と、前の生成画像を参考にする |
| 思いを綴る | 一つの思いを意味の切れ目で分割。1枚1つの考え、段落と余白を確保。目安80〜180文字、上限320文字（正方形220文字） | 新しい背景1枚を全ページで共有。既存背景があれば追加の画像生成なしで再利用 |
| 情報を伝える | 従来のコツ・ノウハウ・番号付き項目。フック、順序立てた解説、まとめ・フォロー案内 | ページごとに生成 |

物語・エッセイのフォロー案内はキャプションに添え、最後の画像は余韻を優先します。入力されていない実体験を捏造しないよう指示し、創作の物語はキャプションで明記する方針です。生成後に内容を確認してください。参考投稿の文章・筋書き・構図は複製しません。

物語・エッセイの編集画面で「文字の位置を動かす」を押すと、文字エリアをドラッグできます。タッチ、矢印キー、左右・上下スライダー、上・下・左・右の配置ボタンにも対応。文字エリアの幅・高さ、文字色、左／中央揃え、半透明の下地の有無も変更でき、PNGと保存済み下書きに反映されます。文字の移動・編集・画像比率の変更ではAPIを呼びません。

画像生成時に文字用の余白と重要な顔・手・小物の安全余白を指定します。現在の画像モデルでは4:5用1024×1280、1:1用1024×1024、9:16用864×1536で生成し、最終PNGは1080px幅に合成します。旧モデルを環境変数で指定した場合は標準寸法に切り替えます。[OpenAIの画像出力仕様](https://developers.openai.com/api/docs/guides/image-generation)。比率を変えて既存画像を使う際は、画像全体を保って配置します。人物の完全一致や余白の厳密な遵守は保証できないため、位置調整と背景の差し替えが可能です。

「イラスト」タブでは、1枚だけ再生成、手持ち画像への差し替え、この背景を全ページで使う、を選べます。エッセイの背景を1枚だけ再生成した後に全ページへ反映したい場合も、「この背景を全ページで使う」を押してください。既存セットは元の情報投稿モードとレイアウトを維持します。

## 人物・文章・文字設定の改善

- 「登場する大人の見た目」は30代が初期値。30／40／50／60代から選べ、読者ターゲットとは別の設定です。保存済み投稿でも「イラスト」タブで変更できます。次の背景生成時に適用し、古い画像は勝手に再生成しません。古い画風指示や参考画像に別の年齢があっても選択年齢を優先するよう指示します。見た目の年齢の厳密な保証はできません。
- ノウハウの中面には、紹介するという宣言でなく具体的な行動・理由・会話例を生成。予告も「紹介します」ではなく、次のページに実在する問いや短い見出しにします。本文・項目本文・強調・予告の宣言表現を生成後に検査し、校正で修正します。旧投稿は「文章全体をAIで校正」で見直せます。
- 物語はまず人物・状況を固定した一つの全文を生成し、その後に意味のまとまりで本文ページへ分割します。表紙と本文ページを別々のスキーマで受け取り、プログラムで完成セットへ組み立てるため、表紙に本文が混ざったり空の本文が出たりすることを防ぎます。隣接する全本文ページの行動・場所・時間・話者・持ち物・結末のつながりを別工程で点検。未解決の問題が残る場合は不完全な投稿を返さずエラーを表示します。意味の正しさを完全に保証するものではありません。既存の物語の全体校正でも、この点検を使います。
- 全モードで字体（明朝体／ゴシック体／テンプレート標準）、自由なHEX文字色、文字背景の透明度を調整できます。透明度0%は濃い背景、100%は背景なしです。PNG・下書きにも反映し、「この文字設定を全ページに適用」で文字設定だけを共有できます。文字設定の変更でAPIを呼ぶことはありません。

## 起動

Node.js 22以上を推奨します（開発環境: Node.js 25.8.1）。

```sh
git clone git@github.com:seira20071004-cyber/mello-post.git
cd mello-post
npm ci
cp .env.example .env.local
```

`.env.local`をローカルのエディタで開き、新しく発行したAPIキーを `OPENAI_API_KEY` に設定してください。キーをチャットやソースコードへ貼らないでください。チャット等で共有されたキーはOpenAI Platformで失効させ、新しく発行してください。

```sh
npm run dev
```

[http://127.0.0.1:3000](http://127.0.0.1:3000) を開きます。開発サーバーはループバックにだけバインドします。キーなしでも「操作サンプルを試す」から編集・保存を検証できます。実生成ボタンはキー未設定の説明を返します。

APIキーは [OpenAI Platform](https://platform.openai.com/api-keys) で発行します。必要に応じてOpenAI Developersの安全なキー設定フローも利用できます。API利用には別途課金設定・モデル権限・画像モデルの組織認証が必要な場合があります。

## 環境変数

| 名前 | 内容 |
| --- | --- |
| `OPENAI_API_KEY` | 必須。サーバーだけで使用するAPIキー |
| `OPENAI_TEXT_MODEL` | 既定 `gpt-5-mini`。文章・校正・画像点検 |
| `OPENAI_IMAGE_MODEL` | 既定 `gpt-image-2.5-flare`。背景イラスト生成 |
| `APP_PASSWORD` | 本番起動では必須。UIで入力するスタジオ共通パスワード |
| `IMAGE_ESTIMATE_USD` | 任意。運用者が設定する画像1枚あたりの参考単価。未設定なら金額を表示しません |
| `USAGE_LOG_PATH` | 既定 `.data/usage.jsonl`。API呼出のメタデータ記録先 |

`NEXT_PUBLIC_` をキー名に付けないでください。キーを返すAPIや、ブラウザでキーを入力する機能はありません。`.env*` と利用ログはGit管理対象外です。設定変更後はサーバーを再起動します。

本番ビルド・起動:

```sh
# .env.local またはホスティング先に APP_PASSWORD を設定してから実行
npm run build
npm start
```

本番では `APP_PASSWORD` がない場合、課金を伴うAPIを503で拒否します。パスワードはUIのメモリだけに保持し、下書きやブラウザストレージへ保存しません。インターネットへ公開する場合はHTTPS、適切な認証・プロキシ設定が必要です。これは個人用MVPで、複数ユーザーのアカウント管理・クラウド下書き共有は含みません。

## 使い方

1. 「40代女性が知っておきたい美容習慣5選」を入力し、ペタル（淡いピンク・ベージュ）、6枚を選択。
2. 「AIで投稿の構成をつくる」を押す。Structured Outputsで生成したJSONをZodで検証し、独立した校正リクエストで文章品質を点検。
3. 6枚の文章・5つの項目・キャプションを確認。表紙＋内容4枚＋まとめに、5項目を `[1,2] / [3] / [4] / [5]` のように分配。
4. 「6枚の背景をつくる」を明示的に押す。1枚ずつ生成・点検し、途中経過を表示。自動的に画像生成へ進むことはありません。
5. スライドを選び、タイトル・本文・各項目・強調語・文字サイズを編集。変更はCanvasで再合成され、AI APIを呼びません。
6. イラストタブから個別生成・背景だけ再生成・スライドの文章と背景の再生成・既存背景の再利用・ローカル画像への差し替え。
7. キャプションを編集。必要なときだけ「文章全体をAIで校正」。文章編集後はキャプションとの意味の一致も確認してください。
8. ダウンロード画面で全スライドをZIP保存。個別PNG、キャプションコピー、UTF-8テキスト保存にも対応。

ZIPは `slide-01.png` ～ `slide-06.png`（枚数に応じて変化）、`caption.txt`、`readme.txt` を含みます。各PNGは選択した比率に合わせて **4:5＝1080×1350px（初期値）、1:1＝1080×1080px、9:16＝1080×1920px** で出力し、1スライド1ファイルです。コラージュ化しません。比率は編集画面から変更でき、既存イラストを再利用して文字配置を組み直すため、画像生成APIを再実行しません。

## 最後まで読みたくなるカルーセル構成

- 表紙はテーマ名だけで終わらせず、読者の悩みへの共感・問い・意外な着眼点・具体的なメリットから内容に合うフックを選びます。
- 中間は「なぜ？→どうすれば？→具体例・実践」と理解が進む流れにします。各ページで一つの答えを渡し、重要な答えを引き延ばして釣りません。
- 各スライドの `nextTeaser` に、直後のページで読める内容を予告。最後の解説はまとめへつなぎ、まとめには次ページ予告を付けません。
- 最後は要点と今日できる一歩、`followCTA` の「フォローすると今後どんなヒントを受け取れるか」で閉じます。
- 入力の「普段の発信内容」を指定すると、フォロー案内へ反映。未指定では関連する今後のヒントを案内し、存在しない過去投稿・肩書き・投稿頻度を作らないよう指示します。
- `lib/composition.ts` で枚数・項目数・配置順を決め、Structured Outputsにも正確な枚数を指定。「5選を6枚」なら表紙・2項目・1項目・1項目・1項目・まとめの6枚です。項目数より解説ページが多い場合は、項目を水増しせず具体例のページを挟みます。
- 「次のスライドへのひとこと」「フォローするメリット・案内」は編集画面で修正できます。
- 新規投稿は4:5。比率未保存の旧セットは9:16を維持して復元し、編集画面で任意の比率へ変更できます。保存済み投稿に新しい構成を取り入れるには「文章全体をAIで校正」を利用できます。
- 生成・校正で構成を点検しますが、閲覧維持率・フォロー率の向上を保証するものではありません。

## マイスタジオで途中から再開

- テーマを入力すると約0.75秒後に自動保存します。AI生成前のアイデアも、空欄を含む編集途中の文章も保存対象です。
- 「保存してマイスタジオへ」で直近の変更を確実に保存し、投稿セットの一覧へ戻れます。新しい投稿を始める際も、編集中のセットを先に保存します。
- 一覧の「続きから編集」で、画像・文章・デザイン・キャプション・画面位置（選択したスライドとタブ）を復元します。保存・復元ではAI APIを呼びません。
- テーマ検索と「入力途中 / 編集中 / 画像生成済み」の絞り込みに対応。
- アーカイブは削除ではありません。「アーカイブ」タブから元に戻せます。
- 旧バージョンの1件の下書きを初回起動時に自動移行し、元の保存データも保持します。
- 一覧には小さな表紙サムネイルだけを読み込み、各セットの画像本体は開くときに読み込みます。
- 別タブの古い編集による上書きを防ぎます。競合した場合は「別セットとして保存」で両方を残せます。
- 保存中にページを閉じる場合には未保存の警告が出ることがあります。「マイスタジオに保存済み」を確認してから閉じてください。保存容量不足や保存機能が使えない場合は画面に表示します。
- 保存先は同じブラウザ・同じURLのIndexedDBです。別端末・別ブラウザ・異なるホスト名には自動共有しません。

## デザインと画像合成

`lib/templates.ts` で共通トークンを管理します。

| テンプレート | 色・フォント・形 |
| --- | --- |
| ペタル | ピンク、ベージュ、Noto Serif JP、丸みのあるカード、花の装飾 |
| リーフ | セージ、アイボリー、Noto Serif JP、広い余白、柔らかい曲線 |
| インク | チャコール、石色、Noto Sans JP、控えめな角丸、端正な配置 |

余白は左右88〜96px、見出しの位置は共通。表紙・項目カード・まとめのレイアウトを用意。自動折り返し、簡易禁則処理、文字サイズ縮小、文字領域のクリップ検出、アクセント上の文字色選択を行います。

日本語フォントは `@fontsource/noto-sans-jp` / `@fontsource/noto-serif-jp` をアプリ内に同梱し、外部フォントCDNは使いません。必要な文字サブセットのロード完了後に描画します。プレビューとPNGの描画エンジンは同一です。比率ごとに余白・カード・フック・次ページ予告・フォロー案内を配置し直します。領域に収まらない文章は警告を表示し、そのPNGの出力を拒否します。

画像APIへは文字・数字・ロゴを含めないよう指示します。背景素材は1024×1024のPNGで作り、最終Canvas上のイラスト領域へトリミングして合成。日本語はすべてプログラムで描画します。画像APIに1080×1920の文字入り画像を直接作らせる方式ではありません。

参考画像はブラウザ内で最大1024px・JPEGへ変換後、文章APIのvision入力と画像編集APIの参照として使用します。参考画像なしの場合、最初に生成した背景を次の画像の画風参照に使用。指定された共通artDirectionも全スライドに渡します。テンプレート変更は文字・色・装飾を更新し、既存イラストを再生成しません。

## 品質・障害対策・費用

- 3〜10枚。明示された項目数が「中間スライド数×2」を超える場合、API呼出前に枚数の変更を案内。
- タイトル内の数字と実項目数、連続ID、各項目がちょうど1回現れること、空欄、文字数、同一見出し・本文、典型的な根拠のない断定表現を検査。
- AI校正で誤字、不自然な日本語、意味上の重複、タイトルと本文の整合、根拠のない断定を検査。医学的エビデンスの検索・出典検証は実装していないため、健康情報の正しさを保証するものではありません。
- 画像生成後にvisionで文字混入、著しい人体破綻、共通画風との不一致を点検。自動判定は完全ではなく、警告を見てユーザーが確認・再生成できます。自動で有料再生成を行いません。
- 文章生成は通常2回（生成＋校正）。整合性の修正が必要な場合だけ追加の校正を1回まで行います。画像1枚は通常2回（画像生成＋vision点検）。参考画像解析は構成生成に含みます。
- 文字・色・テンプレートの変更、手持ち画像、背景再利用、PNG／ZIP出力はAPI呼出0回。
- 初期画質はlow。生成中の停止は処理中の1枚が完了した時点で反映。完了済み画像は保持し、失敗したスライドだけ再試行可能。
- 画像点検だけが失敗しても画像を破棄しません。タイムアウト・429・権限・未設定エラーを日本語で返し、自動再試行は行いません。タイムアウトした呼出がOpenAI側で課金される可能性はあります。
- APIキーを一切返さず、同一origin確認、本番の共有パスワード、8MBリクエスト上限、並行2操作・毎時60操作のサーバー制限を実装。制限・重複リクエスト抑制は単一プロセスのメモリ上で動作するため、サーバー再起動でリセットされます。
- 呼出件数・成功/失敗・時刻・利用トークンを `.data/usage.jsonl` に記録。プロンプト・画像・APIキー・利用パスワードを記録しません。ログ書込み権限がない環境ではコンソールに保存失敗を通知。正確な請求はOpenAIのUsage画面で確認してください。
- テーマごとに複数の投稿セットをIndexedDBへ自動保存します。テーマを入力した段階から、文章・背景画像・参考画像・デザイン・文字サイズ・キャプション・編集中のスライドを保持します。同期・チーム共有・永続的なサーバー画像保存は行いません。ブラウザデータの削除で失われるため完成画像はダウンロードしてください。
