# Googleログインと招待

Googleで本人を確認し、利用権限はmellōで管理します。指定した管理者だけが招待を発行できます。招待は7日間有効で、一つのコードを一つのGoogleアカウントが使えます。利用権限はアカウントに紐付くため、別のブラウザで同じアカウントにログインしても招待の入力は不要です。ログイン状態はブラウザごとに最長30日間です。

ローカルで実際のGoogleログインを試すには、Google Auth Platformでウェブアプリ用のOAuthクライアントを作成し、リダイレクトURIとして `http://127.0.0.1:3000/api/auth/google/callback` を登録します。OAuthアプリをテスト状態にしている場合は、必要に応じてGoogle側にもテストユーザーを登録してください。

`.env.example` のGoogleログイン設定を参照し、ローカルの `.env.local` にクライアントID・クライアントシークレット、別に生成したセッション用の秘密値、管理者メール、オリジンを設定してから `APP_AUTH_MODE=google` で再起動します。秘密値はGitに保存しません。ローカルの招待データは既定で `.data/invites.sqlite` に入ります。

ログイン後、管理者は左メニューの「招待・利用者管理」でコードを発行できます。別のブラウザで招待されたGoogleアカウントにログインし、そのコードを入力して確認します。利用停止は以降の保護されたAPIリクエストから反映されます。

公開環境では公開URL用のGoogle設定と、永続ストレージが必要です。D1を使用する場合は `docs/sql/invites.sql` を適用し、サーバー側のD1設定を用意します。公開環境で永続ストレージを設定しない場合、招待は利用できません。Googleの設定・公開ランタイムへの移植・公開は、ローカル確認とは別の作業です。

マイスタジオや人物コレクションは引き続きブラウザ内に保存されます。招待権限は端末をまたいで使えますが、投稿や人物素材は端末間で同期しません。同じブラウザで別の招待アカウントに切り替えても、各アカウントの投稿と人物素材は個別に表示されます。既存の保存データは管理者が同じブラウザで引き続き使えます。
