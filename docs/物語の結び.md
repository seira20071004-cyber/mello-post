# 物語１・２の前向きな結び

2026-10-27の追加依頼。物語１・物語２の最後の画像に、物語から見つけた具体的な幸せと、短いフォロー案内を同居させる。開発版だけに反映し、公開は別途承認後。

## 構成

最終bodyは「本文の出来事・会話から気づいた身近な幸せ」→空行→「次も読むメリットを添えたフォロー案内」。キャプションだけへ移さない。フォローを促すための別ページや広告帯は作らず、物語１は80文字、物語２は60文字の既存上限内に収める。

気づきの根拠はそれまでの本文に描く。抽象的な万能の名言、育児の正解の押し付け、別れ・後悔・罪悪感による誘導は避ける。普段の発信内容があれば案内のメリットに使い、空欄なら今回のテーマに沿った言葉にする。架空の肩書き・投稿頻度・アカウント名は作らない。

## 反映範囲

全文の下書き、ページ分け、独立した本文校正、最終スライドの再生成に同じ方針を渡す。生成完了時には最終bodyのフォロー案内が抜けていないこともプログラムで確認する。内容が具体的で前向きかどうかはAI校正と目視で確認し、単語の有無だけでは保証しない。

画風・文字方向・枚数・途中の構成・画像生成方式・保存形式は変更しない。フォロー案内は既存のbodyに含めるため、字の編集やPNG保存でもそのまま扱える。専用followCTAフィールドは従来どおり空欄とし、情報モード用の帯を追加しない。

既存の保存済み物語には案内を強制せず、そのまま開く・編集・保存できる。通常の再校正や最終スライドの再生成を依頼したときに、新しい結びを作る。エッセイ・言い換え・いまと未来・情報モードの方針は変えない。

## 検証

物語１・２の全生成工程に方針が渡ること、最終本文に案内が残ること、独立校正で案内が落ちた場合に成功として返さないこと、過去の物語は引き続き検証を通ることをAPIテストで確認。既存の文字レイアウト・画像出力・保存互換性を含む167テストが成功。

実際のAI生成でも両モードを６枚ずつ確認。各モードとも全文作成１回・校正２回で完了し、最終bodyに前向きな気づきとフォロー案内が入り、物語１は80文字・物語２は60文字以内だった。画像APIは呼んでいない。型チェックと本番ビルドも成功。

## 参考投稿を受けた追加調整

前回の「具体的な幸せを説明する」という方針だけでは、「思いやりがあった」「朝が温かくなった」と出来事・感情を報告して終わりやすかった。追加依頼では、本文を読んだ後だから響き、同じ日常の受け取り方が変わる短い心の声を重視する。

- 冒頭の主人公の見方と、本文の小さなきっかけを結びつけて考える。素材にない悩みや失敗を強制しない。
- 途中で関係と動作を具体的に示す。最後は具体物を繰り返す義務をなくし、そこで初めて受け取った関係や意味を短く置く。
- 「つまり」「この物語を通して」などの解説、感情のラベル、どんな話にも付く万能の名言を避ける。参考投稿の特徴的な文章や筋書きはコピーしない。
- 既存の生成・校正の中で結びの評価基準を明示し、一つだけ返す。校正で説明的な要約に戻さない。API工程は増やさない。
- 同じ最終スライドのフォロー案内は空行で分け、締めの一言を削って宣伝にしない。画風・文字数上限・他モード・保存形式は維持する。

167テストと型チェックが成功。文章が「心に来る」こと自体は自動テストの合否では保証できないため、実生成された本文と結びを通読して確認する。

出来事の動作は最終ページの前までに着地させ、最後は心の声を置く。「私は気づいた」と気づきの発生を報告する文も避ける。フォロー案内は12〜20文字程度へ短くし、本文の余韻を優先する。

追加の実確認では、全文生成中に１件が出力上限に達したため、別案を複数考える指示は削除して評価基準に絞った。確認用の既存創作を使った両モードの実校正は、それぞれ２回の本文処理で成功し、文章の締めと同じページのフォロー案内を確認した。画像APIは使わず、ユーザーの保存済み投稿も変更していない。
